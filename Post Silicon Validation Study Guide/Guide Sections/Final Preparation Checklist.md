- Validation-plan structure.
- CPU pipelines and caches.
- DMA and MMIO.
- SoC fabric.
- GPU, NPU, and camera workloads.
- SerDes, BER, jitter, and eye diagrams.
- Power and performance.
- Board bring-up.
- Embedded C.
- JTAG and OpenOCD.
- Schematic review.
- Python test automation.
- Failure analysis.
- DFT fundamentals.

- 60-second introduction.
- GPS debugging story.
- Hardware bring-up story.
- Firmware story.
- Teamwork story.
- Failure story.

- Three questions for the interviewer.

## Day-of reminders

- Start from fundamentals.
- State assumptions.
- Ask for missing technical constraints when necessary.
- Think aloud in a structured way.
- Use diagrams where helpful.
- Define pass/fail criteria.
- Mention observability and logging.
- Include corner cases.
- Discuss recovery and regression.
- Be honest when you do not know something.
- Explain how you would find the answer experimentally.

## Final self-test

Before the interview, make sure you can explain each item aloud without reading:

- JTAG versus SWD.
- Logic analyzer versus oscilloscope versus protocol analyzer.
- DMA and cache coherency.
- MMIO and `volatile`.
- SoC fabric backpressure, arbitration, QoS, starvation, and deadlock.
- SerDes BER, PRBS, equalization, CDR, PLL, and eye diagrams.
- Dynamic versus static power, DVFS, clock gating, power gating, and voltage droop.
- No-boot debug sequence from power to firmware logs.
- How to design a measurable validation plan.
- How to classify pass, fail, infrastructure error, and inconclusive.
