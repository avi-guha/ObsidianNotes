# Lecture

### Making Integers from Bytes
- First Architectural design decision:
	- assembling memory bytes into integers

> [!NOTE] Consider a 32-bit integer
> - uses 4 bytes. If memory address is i, then we require bytes at i + 1, i + 2, i + 3
> - E.G. address of 0x2014, then the integer will be held in 0x2014, ... , 0x2017

### Big-Endian
- Start at the "big end"
- first byte is the most significant,
- used in old IBM servers, network connections
- 0x12345678
- two's complement easier (integers and signing)

then bits $2^{24}-2^{31}$ is held in 0xi (12), and the bits of $2^0-2^7$ are held in 0xi+3 (78)

### Little-Endian
- Start at the "little end"
- least significant byte first. (reversed bytes, BITS ARE STILL IN THE SAME ORDER)
- used in intel-based and many other modern systems
- bits $2^0-2^7$ are held in 0xi (78), and most significant bits are held later (12)
- Nicer if a number is even or odd. Check address instead of having to do 2 read accesses to find 3rd bit.

### Alignment
- Addresses are aligned, if the address is a multiple of the value size
	- depends on the object, gets complex with arrays and structs
	- e.g. all addresses are aligned with 1 byte values
- Aligned Addresses are better
	- can fit two shorts inside of an int,
	- significant in arrays
	- some CPUs straight up don't support misaligned addresses

### Address Alignment = Good
- CPU implementation encourages alignment
- memory organized internally into chunks
- every memory access requires accessing a whole block
- cpu memory access looks like
	- read/write N bytes starting at address A
- this is translated by memory to:
	- block B contains addresses $X..(X+\text{blocksize}-1)$
	- $X \leq A\leq X +blocksize-1$
		- so A is at some offset (lets call it 0) from th ebeginning of block B
		- Read/write n bites starting at Oth byte of block B (A = X + O)
- How is this simplified if:
- blocksize is a power of 2,
- N is a power of 2,
- A is aligned to N?

#### Changing Data Types: Extending
- extending an integer: increasing the number of bytes used to store it
```c++
byte b = -6 // stored as fa
int i = b; // stored as ffffffa
```

Signed extension: used in signed data types
- everything signed in Java
- copy first bit (sign) to extend bits
Zero extension: unsigned data types (C)
- All extended bits to zero

### Changing Data Types: Truncating

# Pre-reading


### The Memory
- Main memory is implemented by a set of memory chips external to the CPU
- Every chip is a DRAM (dynamic random-access memory)
- DRAM bit is implemented by a single transistor and a capacitor
- set of memory chips that implement entire memory is called a DIMM (dual-inline memory module)

Data in memory is named by address. Unique name given to every byte of memory (8 bits). Most data access to memory is 32 bit words (longs). Real CPUs have instructions for accessing memory in 1/2/4/8 byte chunks.

Memory is kind of like an array of bytes, accessible by writing/reading in four-byte chunks at a time. Array index = memory address

| a     | a     | a     | a     | b...     |
| ----- | ----- | ----- | ----- | -------- |
| byte! | byte! | byte! | byte! | byte!... |

#### Machine Instructions
- stored in memory, read by CPU in similar fashion, but using the *PC* and *instruction* registers. Once every cycle the CPU reads the instruction in memory at the address, storing it into the *instruction* register. This is then decoded into various parts.

#### Aligned Access
- Reading or writing multi-byte data from or to memory, access to memory is fastest when addresses used are aligned.
- I.E. -> lower two bits are 0 in 32-bit words == 0,4,8 are aligned addresses ($\text{address} \text{ mod } 4 \equiv0$)
- Every byte of target word will have the same word address. e.g. 8 9 a b are part of an aligned word with byte address 8. In binary -> 1000, 1001, 1010, 1011.
- Bottom 2 bits are simply 0-3, ignoring first 2 bits gives word address of 10
- Allowing addresses to be unaligned means that instructions can read from address 10 to access 10-13. (1010, 1011, 1100, 1101). Different word addresses. (probably means that two accesses are needed in some complex fashion, thus aligned addresses are important)

#### Endianness
- Final issue is to decide how the bytes of emory are assembled to make multi-byte integers. 

> [!NOTE] Example
> Consider the four-byte word. Each word in memory has a byte address, called *$a$*, which means the word is comprised of memory bytes with addresses *$a$*, *$a+1$*, *$a+2$* and *$a+3$*.
> 32-bit numbers are comprised of four bytes, 0-7, 8-15, 16-23, and 24-31. 
> Let $n_{i}$ be the value of bit *$i$* of the number, then the value of the number is 
> $\sum_{i=0}^{31}n_{i}\times 2^i$ (this is just how binary works)
> Into which byte of the number do memory bytes go. This decision is called the *endiannes* of memory: "which end of the egg should be eaten first, the big or little end." Computer systems are divided into Big Endians and Little Endians

##### Big Endian
- eat numbers from the big part of number first. thus byte address *a* is interpreted to store the most significant byte of the number (bits 24-31), and so byte *a+3* will hold the least significant byte, bits 0-7.

#### Little Endian
- converse, eat numbers starting from little end. Byte *a* is the least significant, while byte *a + 3* is the most significant byte (containing bits 24-31).
