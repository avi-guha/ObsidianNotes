## Thread Operations - Block and Unblock
- blocking a thread
	- save a current thread's state; stop it (so it can *wait*) switch to a diff thread
	- **uthread_block();**
	- thread cannot be rescheduled until it is explicitly unblocked (aka the execution that we were waiting one has unlocked our thread)
- unblocking a thread
	- moves thread from queue of blocked to runnable queue
	- **uthread_unblock(t);**

## Thread Operations - Join
- What happens when a thread finishes
	- some threads may want our output
	- we need to keep its information initially (state and return normally.)
- joining with a thread
	- we will **block** a thread until a target thread is **complete**
	- `uthread_join(t, void** rtnValuePtr)`
	- t = our thread to wait for, and our pointer is how we'll be able to access the return value when t continues
- in effect join turns our cpu back into a synchronous operation
	- may still have other threads running

## Thread Operations - Detach
- no thread cares about this one
- damn.
	- **detach** notifies that once it finishes execution free it immediately

## Thread Operations - Yield
- Yielding a thread is being polite
	- save our thread's state and switch to a different runnable thread
	- thread can resume as soon as CPU becomes available (e.g. another thread yields or blocks)
	- threads that yield remain runnable
- rescheduling a thread
	- restores our thread's state and resumes running it
	- yield puts us at the back of the runnable queue (but doesnt care about the other threads)

## Implementing Thread Yield
- Thread Yield
	- puts current thread on ready queue
	- gets next runnable thread from ready queue
	- switches to next thread
- example code
```C
void uthread_yield () {
	// we put ourselves on the queue first cus it might be empty
	ready_queue_enqueue(uthread_self()); // put me on cuh ("this")
	uthread_t to_thread = ready_queue_dequeue(); // get next from queue
	assert(to_thread); // to_thread should not be NULL (otherwise something has gone very wrong)
	uthread_switch(to_thread, TS_RUNNABLE); // switch the thing
	
}
```

## Implementing Thread Switch
- goal
	- implement procedure switch that stops $T_{a}$ and starts $T_{b}$
	- $T_{a}$ calls switch but it returns to $T_{b}$
- requires
	- saving $T_{a}$'s processor state and setting processor state to $T_{b}$'s saved state
	- state is just registers, which can be saved to and restored from the stack
	- TCB has pointer to stack pointer for each thread
- implementation
	1. save all registers to stack (Ta's)
	2. save stack pointer to Ta's TCB
	3. set stack pointer to stack pointer in Tb's TCB
	4. restore registers from stack (Tb's stack)

ping(), ends up calling yield(), which ends up calling switch(), which returns to yield.
THEY ARE PROCEDURES.
as part of the callee prologue to yield we will SAVE OUR RETURN ADDRESS to the stack.
yield will do whatever it needs to and since it calls switch, we'll swap the registers, and pong's return address is then given by switch

## Thread Scheduling
- Scheduling a thread is:
	- deciding which threads should run and when
	- applied when there are more runnable threads than processors
	- involves a policy and a mechanism
- thread scheduling policy
	- set of rules that determines which threads should be running
- possible issues to consider
	- do some threads have higher priority than others
	- should threads have *fair* access to the processor
	- should threads be guaranteed to make progress
	- should one thread be able to *pre-empt* another?

### Priority Round-Robin Scheduling Policy
- Priority
	- A number assigned to each thread
	- thread with highest priority goes first
- when choosing the next thread to run
	- run the highest priority runnable thread
	- when threads have the same priority, run thread that has waited the longest
- implementation (mechanism)
	- organize ready (runnable) queue as PRIORITY queue
		- highest priority first, FIFO otherwise.

### Pre-emption
- pre-emption occurs when
	- a "yield" is forced upon a current running thread
	- current thread is stopped (made runnable, not blocked) to allow another thread to run
- *priority-based* pre-emption
	- when a thread is made runnable with higher priority than a currently running thread, it pre-empts that thread
- *quantum-based* pre-emption
	- each thread is assigned a runtime "quantum"
	- thread will be pre-empted at he end of its quantum
	- how long should this be? depends but typically ~100 ms 

### Implementing Quantum Preemption
- Problem
	- application threads don't have an incentive to check for quantum
	- system schedule needs CPU to run on
	- if application thread is running, system is not. (not multiple cpus)
- Solution
	- the mother fucking *interrupt*
	- I/O controller is connected to a clock
	- interrupt our processor at regular intervals
- Timer interrupt handler
	- compare running time of current thread to its quantum
	- pre-empts if quantum has expired
