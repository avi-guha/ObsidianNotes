#### Problems with Memory Access
- accessing memory is relatively slow (~100 CPU cycles for every memory access)
	- fast programs avoid accessing memory when possible
- big instructions are costly
	- memory addresses are big (instructions are big)
	- big instructions = big programs
	- reading instructions from memory is slow (fewer caching options)
	- large instructions use more cpu resources (transfer, storage)

## Alternatives for Instruction Sets


- Option 1: static address and value (values are right inside of the instruction)
	- $m[0x 10000] \leftarrow 0x 0$
	- 9 bytes (instruction code plus two 4-byte integers)
	- 0.5 bytes instruction code | 4 bytes of address | 4 bytes value

- Option 2: static address, dynamic value
	- $r[0] \leftarrow 0x 0$ *// load a constant value into register*
	- $m[0x 1000] \leftarrow r[0]$ *// store register value in memory*
	- 5 bytes for immediate (constant) value instruction
		- instruction code, register, one integer,
		- 1/2 bytes opcode | 1/2 byte register | 4 bytes of value
	- 5 bytes for memory instructions
		- instruction code, register, one integer
		- 1/2 bytes opcode | 1/2 byte register | 4 byte address

- Option 3: dynamic address and value
	- $r[0] \leftarrow 0x 0$
	- $r[1] \leftarrow 0x 1000$
	- $m[r[1]] \leftarrow r[0]$
	- 2 bytes for memory instruction
		- instruction code (1/2 byte), two registers (2 x 1/2). (CEIL FUNCTION = 2 BYTES)
		- uses 12 bytes
	- more flexibility (address and value can be dynamic)
		- advantage? more memory now = we aren't doing anything else
		- spend some more size of instruction to put values in registers
			- registers can be used as much as we want (registers are 1/2 byte)

### Introduction to a simple CPU
#### The CPU:
- consists of combinational circuitry built from transistors, set of on-chip memory (registers) and a clock
- [[Module 11 - A Working Computer]]
- Combination circuits can implement ANY function, but ONLY functions. (static mapping between two sets, an input set and an output set)

#### Registers:
- adding memory and clock yields a *sequential circuit*.
- numeric values are 32-bits, A and B input wires for the two values being added will be connected to output ports
- in CPU the notion of an addre is extended to something called the ALU.
	- may contain third input F, e.g. F = 3 might cause circuit to compute A + B while A = 4 might cause $a \times b$

#### The Clock
- clock regulates memories as it ticks, precise point on the rising edge. Modern processors typically tick 2-3 billion times a second
- each clock tick allows memory to grab current value,
- every tick starts on a new cycle of the processor
- on each cycle registers provide new inputs to the combination circuit, then computations are made, and this output it presented to input of registers. Then clock ticks again
- Each step is the execution of a single *machine instruction*

#### The Register File
- Could implement ALU using dedicated registers, not ideal for series of operations
- ![[Pasted image 20240912002941.png]]
- i aint writing that shit sorry. tl;dr, dedicated registers are inefficient
- processors use a set of registers called the *register file*
- each bit is connected to a bit of every register in the register file using a MUX.
- Selector is a number between $0\dots n-1$ which picks exactly one of th e value inputs
- picks exactly one of the value inputs to be connected to the output of the multiplexer
- $ALU_{A}$ and $ALU_{B}$ are connected to two different register-file MUXes and $ALU_{O}$ is connected to a DECODER that picks the register to store this output value
	- each connected to register file
	- MUX/DECODER has selector input that specifies register for $ALU_{A}$, $ALU_{B}$, $ALU_{O}$. Input of modified ALU is this $ALU_{sel_{A}}$, $ALU_{sel_{B}}$ and $ALU_{sel_{O}}$ and F: three register NUMBERS and a function number.

Main benefit of this approach is that once initial values are loaded, a sequence of ALU operations can be performed by repeated selecting registers for inputs and outputs.
- Dedicated registers means extra steps are required to move values from inputs to outputs, or to and from main memory where variables are stored.
