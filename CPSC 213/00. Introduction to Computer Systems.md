#### Simple Computing Machine

## Memory
- Naming
	- unit of addressing is a byte
	- every byte has a *unique address*
	- some machines have 32-bit addresses; many have 64-bit addresses is
		- we assume by default we use 32-bit addresses + all addresses are valid
- Access
	- many things are too big to fit in a single byte, unsigned numbers > 255, signed numbers < -128 or > 127 ([[Module 03 - Number Representation]])
	- CPU accesses memory in contiguous (together, connected) power-of-two-size chunks of bytes
	- address of a chunk is the address of its first byte (they are contiguous, then have N bytes following)

#### Numbers and Representation
- interested in *integer value* of a chunk of bytes
- base 10, decimal, we convert from binary
- sometimes we are more interested in the bits themselves
	- e.g. decimal isn't particularly important
	- e.g. memory addresses
		- big numbers that name power of two size things
		- we do not care what base-10 value is
		- we'd like a power-of-two sized way to name addresses
		- simply have to be unique and identifiable (we don't truly care about the value)

##### Binary
- small 256-byte memory has addresses $0_{2}$ to $11111111_{2}$
- may be represented as 0b111111111
- becomes tedious and hard
##### Once we used base-8, octal
- 64-kb addresses go up to = $177777_{8}$
- may be represented as 0o177777
##### Now we use hexadecimal
- 4 GB memory addresses go up to = $\text{ffffffff}_{16}$
- 32 bit addresses.
- if you don't have subscripts can be written as 0x....
- A byte is just 2 hexits ($2^8=16^{2}$)
- 0x6a550ea3 => 0x6a 0x55 0x0e 0xa3

#### Hexadecimal Operations
- we use hexadecimal for addresses (no need for decimal)
- addition/subtraction
	- calculate in hex directly!
	- substitution = add with two's complement
- Remember: 
	- carry when result is 0x10 == $16_{10}$ or more
	- hexits A..F convert to decimal value
