
- sometimes blocking makes more sense, especially if its a dependency

	- if event hasn't happened, then we have an issue blocking call!

## Protection Boundaries
- modern hardware has multiple privilege levels or modes
- different software can run with different levels
- processors typically provide two or more
	- user mode (all applications)
	- kernel mode/supervisor mode: how the os runs
- mostly two; x86 has four, older machines had eight
	- impacts instructions executable (HALT...), unprivileged code
	- read/write any processes's memory, interact with devices
	- OS should have access to some things that are inaccessible to regular processes
	- our mapping information has to distinguish between mapping user processes and the OS

*virtual memory can help us inform some of these*

## x86
- as complicated as it gets.......
Ring 0: OS runs in most privileged here
RINGS 1/2 can be ignored: can run less privileged code, third party drivers etc etc
Ring 3: Application code

**Memory**
- divided up into chunks called segments
- every segment has a privilege level
- processor maintains a current protection level (CPL) usually the protection level of the segment containing the executing instruction
- program can read/write data in segments of $\leq$ privilege than CPL
	- less privileged CPL means higher protection level (and less access)
- program cannot directly call code in segments with more privilege

instructions to increase privilege level
- can user code execute this instruction?
- OS can provide permission
decrease privilege level
- privileged processes
- can user processes do this?
- seems dangerous to not allow privilege to be pruned

## how do we change the privilege level?
- how do we transfer control between applications and the kernel

proposed mechanism: the *trap*

- how does privilege get around the issue?
- tl;dr specify what code gets to execute as a result of the trap. long version is next class

- once down executes lower privilege, jumps from instruction back to the original raise privilege instruction
