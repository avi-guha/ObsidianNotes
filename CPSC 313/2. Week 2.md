### Calling Conventions

*define calling convention*
use y86 calling convention

**How do procedures pass arguments?**
1. on the stack
2. in registers
3. in registers and on the stack

the rules that callers and callees use to communicate information are called calling conventions
the structure used to store this information is called a stack frame

**Parameters**
based on x86 although not exactly
return value goes in %rax
argument/parameters are passed in registers, in this order
- %rdi, %rsi, %rdx, %rcx, %r8, %r9
- more than 6 arguments? push remaining ones on the stack in reverse order

![[Pasted image 20250911231537.png]]

![[Pasted image 20250911230222.png]]

%rsp is the stack pointer
%rbp is the frame (base) pointer

- caller saved registers
	- these are scratch registers - the callee is allowed to scribble all over them, so if the caller cares about their contents, the caller must save them
	- all the argument and return registers + r10, r11
- callee saved registers
	- if the callee uses them, then the callee must restore the original values before returning
	- %rbx, %rbp, %r12, %r13, %r14
	- callee must keep these values the same when they return

### The stack frame
- CALL: use the stack to store a return address
- we also use the stack to:
	- transmit parameters (if we cannot use registers)
	- store local variables
- the structure we use to store this information is called a stack frame

![[Pasted image 20250911230731.png]]

grow from high ordered down to zero (allocating means decrementing)

**Approach 1**:
![[Pasted image 20250911230822.png]]

	- decide how much space we need, allocate it (decrement)

this is called the stack frames

- stack frame also means that we need to tear it down
- we need to increment the rsp, to deallocate local arguments

- get back to stack parameters
- caller should deallocate stack parameters
- now back to only caller's local variables

**Approach 2**: base pointer
![[Pasted image 20250911231122.png]]
- RBP points to beginning of stack frame

	1. now we can access everything off the base pointer
	2. local variables are negative offsets of the base pointer
	3. caller's variables are now positive offsets

**Teardown!**
