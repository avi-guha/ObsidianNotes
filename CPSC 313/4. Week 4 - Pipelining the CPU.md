pros:
- substantially better usage of CPU hardware
- a collection of instructions computes more quickly

cons:
- an individual instruction takes longer (because pipeline registers add latency)
- if some phases take longer than others, short phases are bottlenecked by longer phases

## Terminology
- stage:
	- what we used to call "phase"
	- when we talk about pipelines, each piece of the pipeline is a stage
	- a stage is the unit of computation that the processor performs in a single clock cycle
- instruction statuses
	- **in-flight**: somewhere in the pipeline
	- **retired**: instruction has completed execution
	- go back to the laundry metaphor

*later terminology*

**pipeline register**
- colloquially the extra work we incur by pipelining
- in reality: a register in the processor will capture the set of signals and values to pass on to the next stage so that it can pass it on and continue doing work for the next instruction
- each stage has it's own pipeline register
**hazard**
- the problems that we run into when we naively add pipelining?
- there are cases where we depend on data from previous parts of the pipeline
- there are cases where we jump and modify the PC

### Hazards

- a problem that arises in pipelining when information needed by an instruction is not available when it needs it
	- unless mitigated, hazards can lead to incorrect results
- types of hazards
	1. data hazard. When data dependencies potentially lead to incorrect behaviours (instruction reads from register that another writes)
	2. control hazards. when control dependencies potentially lead to incorrect behaviour

#### Approaches to addressing hazards
- software
- delay execution in hardware (stalling)
- value forwarding in hardware (addresses data hazards)
- branch prediction (address \[some] control hazards) class after that one
