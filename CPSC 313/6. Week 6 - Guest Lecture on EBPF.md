### Safe eBPF
- threat model
- run unprivileged eBPF programs without root access
- unable to load kernel modules or modify kernel code
- can exploit vulnerabilities in the verifier to bypass memory access checks
- only covers temporal memory safety

TCP (trusted computing base)

Software Fault Isolationism:
- we have fixed size of memory and sandbox, we can use a mask so that out of bounds access never occurs since the size is fixed

Memory Tagging with ARM NTE:
- happens during memory allocation
- each 16 bytes of emmory is associated with a tag
- tag in pointer should match that in physical memory
	- eBPF sandbox uses different tags than base kernel to detect out of bounds access

## Caching
- collloquially: store away in hiding or for future use
- applied to computation
	- placing data somewhere it can be accessed more quickly
examples:
- in assembly language: we move data from memory to registers
- in the hardware: we move data from main memory into memory banks that live on the processor
- in software: we read things into our program's local buffers and manipulate them there
