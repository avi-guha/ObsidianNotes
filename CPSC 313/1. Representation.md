## y86 hardware
- what is visible to someone actually programming in assembly!
- registers are used for high speed memory
- grouped together in a **register file**
	- 15 registers
	- special names match registers used for intel x86 architecture
	- rax, rcx, rbx, rdx
- r4 = %rsp (the stack pointer)

### ALU
- condition codes
	- collection of bits set by arithmetic and logical instructions
	- ZF: zero-flag = last ALU operation produced a 0
	- SF: sign flag = last ALU operation produced a negative number
	- OF: last alu operation produced an overflow

### Status
- indicates normal operation or an error condition
- 1. AOK is a ok!
- 2. HLT = halt instruction encountered
- 3. ADR bad address
- 4. INS invalid instruction encountered

### Program Counter (PC)
- address of next instruction to execute

### Main Memory (DMEM/DRAM)
- where data is ultimately stored
- words are stored in little endian order

### Instruction Classes
- simple instructions: halt, nop
- move instructions: rrmovq*, irmovq, rmmovq, mrmovq
- stack operations: pushq, popq
- arithmetic and logical oipeartions: addq, subq, andq, xorq
- jump instructions: jmp, jle, jl, je, jne, jg, jge
- function call and return: call, ret

ALL instructions have a similar anatomy


2 byte instructions (all instructions first byte follows same two nibbles, op and function)

| op  | fun | rA  | Rb  |
| --- | --- | --- | --- |

9 byte instructions are op, fun, and a destination (64 bit address)
10 byte instructions are op, fun, rA, rB, and a 64 bit value


halt [0,0] set program status register to HLT
nop [1,0] do nothing

# Move instructions
- move from one register to another
- R[%rB] <- R[%rA] (we are taking the contents in rA, and moving it to rB)

### **RRMOVQ (register to register move quadword)**
[2,0, rA, rB] - opcode = 2, fn = 0.. but flexibility
2089 = move contents of register 8 to register 9

### **IRMOVQ (Move immediate value to a register, q = quadword)**
- val = 8 byte constant, 9 byte instruction

[3, 0, F, rA, val...]
- f is used to indicate an unused register

IRMOVQ 0xCAFE, %r9 = 0x000000000000CAFE

LITTLE ENDIAN ORDER
... above example becomes
30, F9 (fine because individual bytes), FE, CA, 00, 00 ...

### **MRMOVQ (Memory to Register move quadword)**

R[%src_register] <- $M_{8}$[D + R[%from_register]]
8 refers to values stored in memory (quadwords, 8 bytes)

MRMOVQ 4(%rsp), %r9 (4 is the offset)
