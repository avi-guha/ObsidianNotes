## Amdahl's law
- evaluate cache performance by calculating speedup
- originally designed to quantify opportunities and benefits of parallelism

 if you have a program that has a sequential part and a parallelizable part. When you parallelize it, you will only improve the performance of the latter. So it's good to know just how much parallelizing the application will help.

given latency $T_{old}$
you can speed up part of a system by a factor of k
program spends $\alpha$ (< 1) of its time in the part that will speed up

Latency after improvement
$$
\begin{align}
T_{new} &= T_{old}(1-\alpha) + T_{old}\left( \frac{\alpha}{k} \right) \\
T_{new} &= T_{old}\left( 1-\alpha + \frac{\alpha}{k} \right)
\end{align}
$$

Speed up = Told / Tnew
so $\frac{1}{(1-\alpha) + \frac{\alpha}{k}}$
you know the formula already

## Write Policy Tradeoffs

- advantages of writeback cache (disadvantage of write through)
	- writes are expensive
	- we run at speed of cache most of the time
	- otherwise we run at speed of the source
	- you can overwrite the same location as many times as you want (when its not evicted)
	- write coalescing (update the same item) ^

- advantages of writethrough cache (= disadvantage of write back)
	- mr essay strikes once again
	- done all the work of the writes in advance of doing the eviction (no dirty data, ever)
	- have to write a dirty cache line to data source (to evict) before we can update it
	- if you write to the file system you may actually want to use write through... when the file gets evicted it might take a LONG while to actually ever update the file (that file might get held in RAM for hours)
	- no window of vulnerability

## Anatomy of addresses and cachelines
- address
	- offset
		- selects starting byte in a cache line
		- log2(cache line size)
	- index
		- selects cache set
		- log2(# of sets)
	- tag
		- identifies lines in set using associative lookup
		- num bits left

- metadata
	- valid bit
		- 1 iff (and only if) line contains valid data (0: no data is meaningful)
	- tag
		- used to determine which address is stored in the cache line: for a hit the tag bits in the address must match the tag bits in the metadata in set indicated by address index bits
	- for writeback (dirty bit)
		- 1 iff line contains dirty data
	- as necessary for replacement polciy
		- LRU info etc

## Write Performance: Hits
- write through cache
	- data is written to both the cache and the source
	- latency is write to data source (or whichever is slower, we do it in parallel)
- write back
	- only written to cache
	- dirty bit in the cache line metadata is set to 1
	- latency is ~= time to write to cache

- no write allocate
	- data is written to the source
		- cache is checked, but is unchanged
- write allocate
	- acts like read miss
	- read from data source + write to cache
	- benefits where read locality mirrors write locality
