### Associativity summary
- a kway set associative cache with n total slots for lines
	- has n/k sets, each with k slots
	- each cache line in memory can go in oen and only one set
	- which means
		- a direct mapped cache is "1-way set associative"
		- each set if effectively it's own fully associative cache for its ow parts of memroy if a set is full
			- we need a wayto decide what to evict and what to bring in
- the number of sets n/k must be a power of 2. The number of slots per set k and the number of cache lines n may not be

### What happens when a set is full!
- each set has a limited capacity
- when the application wants another item that belongs in a full set
- caching the new item means we evict something else
	- what do i evict?
		- we need an eviction policy
			- why didn't we need this for direct mapped? (we can only make one choice)
	- available decisions vary between hardware and software

## Evictions in hardware
- frequently have a few choices
	- direct mapped (1)
	- k-way set associative: k choices.
- it is typically too expensive to build fancy replacement algorithms into hw caches, so we often use a random replacement policy

## Eviction in software
- in a perfect world, we would evict the item that is least valuable
- in the real world, we would like to, but we don't know what that item is (the one that will be used the farthest away)
- practically all eviction policies try to approximate this ideal
	- and as such we use heuristics to determine which is the least valuable

**examples**
- LRU cache (least recently used) - find item that has been unused the longest and get rid of that
- LFU: least frequently used find item that has been used least frequently and get rid of that
- clock: used in virtual memory systems to approximate LRU (learn later, an approximation of an approximation)
- something tuned to known access pattern
- cool live-updating, real-access-pattern-based, learned policies
	- we don't this in hardware... definitely not!
